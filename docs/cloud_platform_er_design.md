# 云平台E-R设计文档

## 设计背景

根据云平台API接口规范，设计一个最简单但可扩充性极强的E-R图，支持用户管理、终端管理、指令发送等核心功能。

## 核心实体分析

### 1. 用户实体 (User)

**实体定义：**
```
┌─────────────┐
│    User     │
├─────────────┤
│ id (PK)     │
│ username    │
│ password    │
│ email       │
│ role        │
│ status      │
│ created_at  │
│ last_login  │
└─────────────┘
```

**属性说明：**
- `id`: 主键，用户唯一标识
- `username`: 用户名，唯一
- `password`: 密码（加密存储）
- `email`: 邮箱地址
- `role`: 用户角色（Administrator, Manager, Editor, Operator, Monitor）
- `status`: 用户状态（ACTIVE, INACTIVE, LOCKED）
- `created_at`: 创建时间
- `last_login`: 最后登录时间

**设计依据：**
- 根据登录接口 `/wp-login.php` 的用户认证需求
- 根据指令接口的授权角色要求：'Administrator','Manager','Editor','Operator','Monitor'
- 支持用户权限管理和状态控制

### 2. 终端组实体 (TerminalGroup)

**实体定义：**
```
┌─────────────────┐
│ TerminalGroup   │
├─────────────────┤
│ id (PK)         │
│ name            │
│ description     │
│ parent_id (FK)  │
└─────────────────┘
```

**属性说明：**
- `id`: 主键，终端组唯一标识
- `name`: 终端组名称
- `description`: 终端组描述
- `parent_id`: 父级终端组ID，支持层级结构

**设计依据：**
- 根据终端列表接口的 `terminalgroup` 参数
- 根据接口文档中的终端组信息：`"terminalgroup": [{"name": "终端组12", "id": 66}]`
- 支持终端的分组管理和权限控制

### 3. 终端实体 (Terminal)

**实体定义：**
```
┌─────────────┐
│  Terminal   │
├─────────────┤
│ id (PK)     │
│ title       │
│ status      │
│ author (FK) │
│ date        │
│ group_id(FK)│
└─────────────┘
```

**属性说明：**
- `id`: 主键，终端唯一标识
- `title`: 终端名称
- `status`: 终端状态（publish等）
- `author`: 创建者ID，关联用户
- `date`: 创建时间
- `group_id`: 所属终端组ID

**设计依据：**
- 根据终端列表接口 `/wp-json/wp/v2/leds` 的响应数据结构
- 根据接口文档中的终端信息：`"title": {"rendered": "终端123"}, "author": 106`
- 支持终端的创建、状态管理和分组归属

### 4. 指令实体 (Command)

**实体定义：**
```
┌─────────────────────────────────────┐
│           Command                   │
├─────────────────────────────────────┤
│ id (PK)                            │
│ post (terminal_id FK)              │
│ content (JSON)                     │
│ act_url                            │
│ act_method (0-GET,1-POST,2-PUT,3-DELETE)│
│ status (PENDING,EXECUTING,SUCCESS,FAILED)│
│ created_at                         │
│ author (user_id FK)                │
└─────────────────────────────────────┘
```

**属性说明：**
- `id`: 主键，指令唯一标识
- `post`: 目标终端ID
- `content`: 指令内容（JSON格式）
- `act_url`: 指令执行URL
- `act_method`: HTTP方法（0-GET, 1-POST, 2-PUT, 3-DELETE）
- `status`: 指令状态
- `created_at`: 创建时间
- `author`: 指令创建者ID

**设计依据：**
- 根据指令接口 `/wp-json/wp/v2/comments` 的请求参数
- 根据接口文档中的指令示例：
  ```json
  {
    "post": 1,
    "metadata": {
      "act_url": "api/action",
      "act_method": 1
    },
    "content": "{\"command\":\"wakeup\"}"
  }
  ```

## 实体关系设计

### 1. 用户-终端组关系 (M:N)

**关系表：**
```
┌─────────────────────────────────────────────────────────┐
│              user_terminal_groups (M:N)                │
├─────────────────────────────────────────────────────────┤
│ user_id (FK)                                           │
│ terminal_group_id (FK)                                 │
└─────────────────────────────────────────────────────────┘
```

**设计依据：**
- 根据接口文档中的授权角色要求
- 支持用户对多个终端组的访问权限
- 支持终端组对多个用户的权限分配

### 2. 终端组-终端关系 (1:N)

**关系：** TerminalGroup (1) ←→ (N) Terminal

**设计依据：**
- 根据终端列表接口的 `terminalgroup` 参数
- 支持终端的分组管理
- 支持层级终端组结构

### 3. 终端-指令关系 (1:N)

**关系：** Terminal (1) ←→ (N) Command

**设计依据：**
- 根据指令接口的 `post` 参数（终端ID）
- 支持一个终端接收多个指令
- 支持指令历史记录和状态跟踪

### 4. 用户-指令关系 (1:N)

**关系：** User (1) ←→ (N) Command

**设计依据：**
- 根据指令接口的权限控制需求
- 支持指令创建者记录
- 支持指令审计和权限验证

## 设计优势

### 1. 简单性
- 核心实体只有4个，关系清晰
- 每个实体职责单一，易于理解和维护
- 符合当前接口规范的需求

### 2. 可扩展性
- 支持用户权限管理（基于角色的访问控制）
- 支持终端分组管理（支持层级结构）
- 支持指令历史记录和状态跟踪
- 预留了节目、素材、排程等扩展空间

### 3. 灵活性
- 指令内容使用JSON存储，支持各种指令类型
- 终端组支持层级结构，满足复杂组织需求
- 用户权限可以灵活配置，支持细粒度控制
